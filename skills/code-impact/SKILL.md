# 改动已有代码前，先算后果

> 把下文的 `repo-guard` 换成实际安装的命令名。**没装工具也能用这个技能**，见最后一节降级。

本技能回答一个搜代码做不到的问题：**改这个东西，会波及哪些用户可见的入口（页面 / 接口）。**

## 一句话判据

**改或删已有公共层 → 必查影响面。写新页面 → 先看仓里同类。新建公共组件 → 先看高扇入热点。**

| 必查 | 不必查 |
|---|---|
| 公共目录（组件 / hook / service / 工具 / 路由 / 状态）下**已存在**的文件 | 纯样式、纯文案改动 |
| 新建页面 | 新建只被一处使用的叶子组件 |
| 新建公共组件 | 只加不改（新增可选参数、新增函数） |
| 任何改函数或组件**签名**的动作 | |
| 任何**删除**代码的动作 | |
| 改接口的出入参 | |

准确的公共层目录以本仓配置为准，各项目约定不同。

## 别为了用工具而空跑

| 要回答的问题 | 用什么 |
|---|---|
| 这个函数在哪些文件被调用（名字唯一、一次搜得完） | **搜代码** |
| 这个入口怎么走到实现（路径在路由文件里能一次读完） | **先读文件**，不必空跑工具 |
| 改它会波及哪些**页面**、要回归哪些入口 | **必须查影响面** |
| 这个页面实际打哪个后端接口、出入参字段是什么 | **必须查调用链** |
| 这类页面仓里怎么写、抄哪几个 | **必须查同类页** |
| 写新组件前，仓里有没有现成的高复用件 | **必须查热点** |

单文件小改上工具不是质量杠杆。实测：单链路走图谱约 165 秒，直接搜代码约 80 秒，**慢约一倍**——单链路本就是搜代码的活。空跑既显得工具没用，也浪费一轮。

## 怎么查

```
repo-guard impact <仓库根相对路径>
```

返回四样：

| 返回 | 怎么读 |
|---|---|
| **直接调用者** | 谁直接用了它，带文件、函数、行号 |
| **依赖模块** | 沿 import 链往外最多三跳 |
| **受影响的页面 / 接口** | 带分数。**这是你真正要回归的清单** |
| **强影响数** | 分数 ≥ 0.5 的，表示"直接调用或直接渲染"，不是间接依赖 |

**拿到结果之后：**

- 受影响入口 **≥ 5** 个 → 只允许新增可选参数，**不要改已有签名**
- 有强影响 → 在回复里列出必须回归的入口
- 影响面为 0 → **见下一节，不要当成"可以安全删"**

## 盲区：返回空不等于没人用

每次查询都会附一份盲区清单。常见的有：

- 动态 import、运行时拼接的路径
- 样式文件的引用关系
- **SQL 文件、离线任务、其它服务里的引用**——这些完全在图谱之外

所以：

> **影响面为 0 ≠ 可以删。** 只说明"在图谱能看见的范围内没有调用者"。
> 删除任何对外可见的东西之前，先确认它不是留给外部调用方的。
> 拿不准就停下来问，不要替用户决定。

## 没装工具时怎么办

不要调用不存在的命令。改用搜代码兜底，并且**必须在回复里明说**：

> 本仓未安装影响面工具，以下结果来自代码搜索，**可能不完整**——动态引用、SQL、离线任务都搜不到。

然后照样遵守上面的判据：搜到 ≥5 处调用就不要改签名，搜不到也不要当成可以删。
