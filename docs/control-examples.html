一条故事走六层

任务：「把订单状态简化一下，公共 Button 顺手重构，字段改个名。」同一条需求，六次刹车各卡一点。

1 事实
开场已注入：公共层是 src/components，组件库是 Tea。Agent 不用自己猜 Button 算不算公共件。
2 过程
直接改 Button.tsx → 没查 impact，不准写。文案一个字都还没动，手续没做完。
3 图谱
去查 impact：12 个页面在用。只允许加可选参数，不能改已有签名。
4 红线
仍想把 order_status 改名 → 真 diff 里这个名字变少 → 拦住。外部对账还在用这个字段。
5 人决策
非要破例：正规是 canUseTool 卡住，脚本开飞书/企微审批，leader 过了才 allow。本机 ask 只问操作者。
6 合并
本地改完了：git push 宿主先问人；MR 还要 CI 绿 + 必审人。没过仍进不了主干。
knowledge · 不拦截

工程事实

把代码里读不出来、但 Agent 每次干活都必须看见的短事实写入仓库。会话一开始自动注入。这里只注入，不拦写入。

  1. 写什么：公共层目录、组件库包名、权威文档/设计稿路径、环境与隔离、模块专属事实
  2. 不写什么：操作步骤（技能）、名字禁令（红线）、「必须先查影响面」（过程门禁）
  3. 怎么生效：短句进 CODEBUDDY.md；按路径进 rules；机器摘要进 facts.json
  4. 边界：公共层清单必须人看过一眼，禁止只靠目录名自动拦

是否人审 否 · 运行时不弹窗

配置阶段确认公共层目录猜得对不对。猜错会漏拦或天天误伤。

示例

1 · 发生了什么

新会话开始。仓库已写明公共层是 src/components，组件库是 Tea。

2 · 这一层怎么卡

不卡。只把这几句塞进上下文，后面改 Button 时过程门禁才用得上这份清单。

3 · 谁拍板

无人审。人只在 init --write 后核对公共层有没有猜错。

规范：CODEBUDDY.md / .codebuddy/facts.json · PLUGIN-LAYERS.md

constraint · 内容

红线

防止 AI 把对外还在用的字段、接口、错误码删掉或改名——这些名字一少，外部调用方就会挂。 人把「绝对不能动的名字」写进仓库；AI 一改文件，机器数这个名字在这次改动里是不是变少了，少了就拦住。

  1. 锁是什么：点名的字段/函数/错误码 + 作用路径。原因给人看，机器不靠它判
  2. 何时拦住：受保护名字在真 diff 里出现次数变少 → 默认直接拒绝
  3. 拦不住什么：没点名、只改含义没改名字、用 shell 绕开文件工具
  4. 配完必做：跑 audit，别守空气、别留路径后门。规则必须进 git

是否人审 可配置

默认无人审，机器拒绝。打开人决策后才弹窗问「这次能不能破例」。

示例

1 · 发生了什么

Agent 把 order_status 改名为 status。外部对账接口还在认旧名。

2 · 这一层怎么卡

对照这一次真 diff：这个名字变少了 → deny。手续齐了（已经查过图）也会拦，因为内容违规。

3 · 谁拍板

默认机器。要破例才走人决策（本机或 leader 审批）。

规范：REDLINES.md

capability · 拉

图谱

模型猜不准、全文搜索也看不见「谁在用、会波及谁」。图谱按当前代码现算出结构图（不进 git）。

  1. 依赖图：文件 / 模块谁引用谁
  2. 调用图：函数、组件、接口谁在调谁（含页面渲染、HTTP）
  3. 入口图：对外页面、HTTP 路由（影响面的终点）
  4. 契约图：从真实调用点反推接口传了哪些字段
  5. 页面结构图：每个页面用了哪些组件和写法，用来找同类页
工具常见场景（一句）
impact改已有代码前，看会波及哪些页面 / 接口
similar写新页面前，看本仓同类页面已经怎么写
hot写新的公共能力前，看仓里什么被大量复用
lib_search写新组件前，看本仓组件库有没有现成的
trace顺着这个页面 / 接口，把真实调用链走一遍
contracts从调用点起草接口字段（必须人看过才能当类型）
scan体检超长文件和循环依赖，可挂流水线

是否人审 否

查询本身不问人。contracts 草稿必须人看过再落库。

示例

1 · 发生了什么

过程门禁拦住之后，Agent 去查 Button.tsx 的 impact。

2 · 这一层怎么卡

图谱不拦写入。它给出：12 个页面在用，盲区里还有动态引用。影响面 0 ≠ 可以删。

3 · 谁拍板

无人审。写文件的瞬间禁止现建图；空图必须报失败，禁止当成「没人用」。

规范：GRAPH.md

constraint · 手续

过程门禁

红线拦的是改出来的内容违不违规；过程门禁拦的是这步做了没有、该查的查了没有。 内容完全没问题，手续跳过了，照样不准写。

  1. 先查图谱再动手（出厂开的是前半句）：改公共层已有文件，没查过波及谁就不准写；新建页面/组件，没查过仓里同类写法和现成组件也不准写
  2. 别转圈：同一件事反复失败 → 拦住
  3. 别改太散、别动冻结代码：一次改太多文件（多半理解错了），或动到「先找人」的历史/生成代码 → 不准写
  4. 改完要有检查痕迹：改了文件却没跑测试/检查 → 提醒或不准宣布做完

是否人审 否

手续没做完 → 直接拒绝，不交人拍板。

示例

1 · 发生了什么

Agent 只改 Button 上的一句文案，一个对外字段都没动，但本轮没调过 impact。

2 · 这一层怎么卡

Write 被 deny。和红线不同：内容可能完全合规，缺的是手续。

3 · 谁拍板

机器。查过 impact 再写，过程门禁放行；若再去删受保护名字，才轮到红线。

规范：PROCESS-GATES.md

human · 交回人

人决策配置

规定什么时候把决定权交回人。本机弹窗问的是键盘前的人；要指定 leader，走 canUseTool 调公司审批。

  1. 硬（弹窗，不点过不去）：红线已经命中。机器先拦住，弹出确认框
  2. 软（只劝问，不保证停下）：需求两种读法、删表/无回滚。模型不问，写入照样发生
  3. 打开后也不弹窗：没查影响面、转圈、动冻结代码 → 仍由过程门禁直接拒绝
  4. 不要配进来的：git commit、生产写、合入主干 → 走合并门禁

是否人审 是 · 仅弹窗那一档强制

弹窗时拍：这个已上线的名字能不能破例；外部调用方会不会断。

示例

1 · 发生了什么

红线已拦住 order_status 改名。业务坚持这次必须改。

2 · 这一层怎么卡

默认仍是 deny。打开本机 ask → 操作者点允许。正规：canUseTool 卡住，等 leader 在飞书/企微点通过才 allow。

3 · 谁拍板

本机 ask = 操作者。指定 leader = 公司审批流。合入必审人是合并门禁，不替代当场卡住。

备注 · Leader 审批怎么接（canUseTool）
宿主 SDK 在工具真正执行前回调：canUseTool(工具名, 入参) → allow | deny。红线命中时回调里先不放行，脚本开飞书/企微/工单（指定 leader），卡住等结果，通过才 allow。这是指定审批人、双人复核的唯一可行位置。Channel 白名单只是群里能点的人都能审；human-review.json 的 ask 只问操作者。审批「谁批了什么」要自己写审计日志。

规范：HUMAN-REVIEW.md · 调研：CONTROL-POINTS.md §13

outside ReAct

合并门禁（Agent / 工程）

过程门禁卡的是这一轮写不写得成；合并门禁卡的是写完了进不进主干、危险命令现在能不能跑。 CODEOWNERS / 保护分支是 git 平台自带的，插件不重复造。

工程侧 · 进主干

  1. 构建 / 测试不过 → 不能合
  2. lint / 类型 / 风格不达标 → 不能合
  3. 安全与依赖不合规 → 不能合
  4. 保护分支、必审人、CODEOWNERS 没过 → 不能合

Agent 侧 · 危险命令

  1. git commit / push → 宿主 permissions.ask 先问人
  2. kubectl / 连生产库 → 同样 ask
  3. 插件只给示例 JSON，不会自动生效，要人贴进宿主配置
  4. 人在自己终端敲 commit，不走 Agent 权限

是否人审 是 · 合入时 / 危险命令时

示例

1 · 发生了什么

红线破例已批，文件改完了。Agent 执行 git push，并开 MR。

2 · 这一层怎么卡

push 命中宿主 ask → 本机确认框，不点命令不跑。MR 还要 CI 绿 + 必审人。插件 Stop 上不拦 commit。

3 · 谁拍板

危险命令：键盘前的人。进主干：流水线 + 平台上的 leader。不审「有没有查过 impact」。

规范：MERGE-GATES.md

skill · MCP

组件规范

用哪套库、何时允许新建、公共组件怎么改。包名锁在事实里；具体 props 查组件文档 MCP。lib_search 只回答库里有没有。

  1. 以 repo-facts.componentLibrary 为准，禁止再引第二套
  2. 写前查 componentMcp 的文档/API，不要凭 antd / MUI 记忆写内部库
  3. 新建：先 lib_search，再 hot；没有现成的才自己写
  4. 改已有公共件：先 impact；入口 ≥ 5 只加可选 prop

示例

1 · 发生了什么

Agent 要写多选下拉，按 antd 的 API 往 Tea 组件上套。

2 · 这一层怎么卡

开场已要求先查组件 MCP。内部库不在训练数据里，凭记忆写的 props 几乎一定是错的。

3 · 谁拍板

用法不弹窗。「新建必查」要过程门禁开闸；破坏性改签名再走人决策。

规范：COMPONENT-SPEC.md

skill · 不硬拦观感

UI 规范

怎么按本仓设计规范落地页面。机器能提醒别写裸色值；像不像稿只问人，不硬拦。

  1. 权威源写死（Figma 或原型），两个源不一致不要自己折中
  2. 颜色/间距/字号走本仓 token，不要写裸色值
  3. 空态 / 加载 / 异常 / 栅格要齐
  4. 写完可 remind；真禁裸色值走 lint
  5. 像不像稿：插件没有像素对比，拿不准就问人

示例

1 · 发生了什么

列表页只写了有数据的表格，按钮写死红色十六进制。

2 · 这一层怎么卡

写后提醒：裸色值、缺空态/加载/异常。不在写前 deny。

3 · 谁拍板

像不像稿、两个设计源打架 → 问人。用哪套组件库不在这里审。

规范：UI-SPEC.md
