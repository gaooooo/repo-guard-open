时刻是什么有没有 hook本分类写不写资料
T0进程启动：环境变量、CLI（--permission-mode、--plugin-dir）无不写。机器怎么启动，不是规范内容。
T1配置装配：settings 四层合并；hooks 注册表在此刻拍快照；目录信任检查无不写。改的是宿主配置，不是工程事实/技能/红线正文。
T2扩展发现：插件、skill、MCP、LSP、bin 入场无（注册本身不是 hook）技能库索引、图谱/组件 MCP 在这里登记。
T3上下文装配：CODEBUDDY.md、.codebuddy/rules；skill 只装 name+description无工程事实主入口。
T4会话开启SessionStart公共层、红线摘要、停止条件（何时问人，自觉）。
T5用户提交提问UserPromptSubmit按任务点名 skill、补「去读」路径。
T6模型决策：skill 正文展开；条件规则命中才注入InstructionsLoaded技能正文；rules 的 paths 条件事实。
T7工具调用（拦 → 人审 → 宿主执行 → 跑 → 写后）Pre/PostToolUse 等过程门禁、红线、人审、图谱调用。
T8子代理、工作树、MCP 问人Subagent* / Elicitation* 等人审（MCP）；多数编码主路径轻。
T9上下文压缩PreCompact / PostCompact压缩后必须重注工程事实。
T10本轮停止（可打回 T6）Stop / StopFailure过程门禁提醒；不在这里硬拦 commit。
T11会话结束SessionEnd治理留痕，不进 git。

rules 算哪一类？

分类表里没有单独写 rules，因为它不是第十二类资料，而是工程事实的第二种写入节点（和 CODEBUDDY.md 同属上下文注入）。

写入节点何时进上下文该放工程事实里的哪一段
CODEBUDDY.mdT3 全量注入每次都要看见的短合集：公共层、包名、权威源路径。
.codebuddy/rules/*.mdalwaysApply:true 则同 T3；false+paths 则 T6 碰到匹配文件才注入一次模块/端专属事实，避免根文件膨胀。例如只在改 css/tsx 时注入 UI token 路径。

不要把技能正文、红线清单、门禁脚本写进 rules。skill 走 skills/；红线走结构化规则+PreToolUse；门禁走 hook。rules 只承载「仍是事实、但不必每次提问都常驻」的那一层。
