# 09 数据与存储

> 覆盖访问规范、事务边界、数据变更与迁移、缓存、数据生命周期与分区。
> **本维度定义「缓存三态」「写放大边界」两个概念，其余维度引用不重述。**
> 数据结构变更的**兼容性判据**见 `03-change-compatibility`，本维度只讲**执行规范**。

## 概念定义

| 概念 | 定义 |
|---|---|
| **缓存三态** | 缓存查询的结果必须可区分三种状态：**命中有值**、**命中空值**（已确认数据不存在）、**未命中**（缓存中无此记录）。另有第四种独立状态：**缓存故障**。四者混淆是缓存类缺陷的主要来源 |
| **写放大边界** | 单次业务操作允许触达的数据行数上限。超出边界的操作须改为分批执行并具备中止能力 |

## 一、数据访问规范

### 必须

- **`必须[H]`** 查询条件中的值一律通过参数绑定传入，禁止拼接。无参数绑定通道时须使用类型化白名单完整匹配，校验失败即拒绝且不得清洗后重试。安全要求见 `14-security-baseline`。**违反的表现**：输入可改变查询语义，造成越权读取或数据损坏
- **`必须[H]`** 标识符类（表名、字段名、排序字段）不得由外部输入直接决定，只能通过枚举白名单映射。**违反的表现**：输入可指向任意数据对象
- **`必须[H]`** 所有数据访问必须设超时，且纳入所在链路的超时预算。超时要求见 `06-resilience`。**违反的表现**：慢查询占满连接，服务整体阻塞
- **`必须[H]`** 客户端与连接池必须复用，不得按请求创建。连接池容量须设上限。**违反的表现**：连接数随流量线性增长，耗尽服务端连接配额
- **`必须[H]`** 只查询实际需要的字段，禁止无差别取全部字段。**违反的表现**：大字段被无谓传输，且新增字段后隐式改变传输量
- **`必须[H]`** 查询结果必须有数量上限，不得返回不受限的全量结果。分页要求见 `04-api-contract`。**违反的表现**：数据增长后单次查询耗尽内存
- **`必须[H]`** 更新与删除必须带明确条件，且预估影响行数须在写放大边界内。**违反的表现**：一次误操作影响全表
- **`必须[H]`** 必须区分「查询无结果」与「查询失败」，二者不得返回相同结果。**违反的表现**：故障被当作数据不存在，触发错误的业务分支
- **`必须[H]`** 慢查询与异常查询必须可观测，含查询特征与耗时。**违反的表现**：性能劣化无从定位

### 推荐

- 查询语句集中管理，避免散落在业务逻辑各处
- 为高频查询显式设计访问路径，不依赖存储层自动优化
- 批量读写按固定规模分批，规模作为配置项
- 读写分离时明确各查询的一致性要求

## 二、事务与一致性

### 必须

- **`必须[H]`** 事务边界必须最小化，只包含必须原子化的操作。**违反的表现**：长事务持有锁，并发能力急剧下降
- **`必须[H]`** 禁止在事务内执行跨进程调用。**违反的表现**：外部依赖变慢导致事务长期挂起，连接池耗尽
- **`必须[H]`** 事务内不得包含可能长时间阻塞的操作（大批量处理、外部等待）。**违反的表现**：锁持有时间不可控，引发大面积等待
- **`必须[H]`** 跨存储的操作不得假设原子性，必须显式设计一致性方案并声明中间态的可见性。**违反的表现**：部分成功后数据处于无人处理的中间状态
- **`必须[H]`** 并发更新同一数据时必须有冲突控制机制，不得依赖执行顺序。**违反的表现**：并发写互相覆盖，数据静默丢失
- **`必须[H]`** 事务失败后的补偿路径必须明确，不得只回滚本地而遗留外部副作用。**违反的表现**：本地回滚但外部已产生副作用，数据不一致
- **`必须[H]`** 必须显式声明所需的一致性级别，不得默认最强或最弱。**违反的表现**：读到未提交或过期数据而未预期

### 推荐

- 优先通过业务设计避免跨存储事务需求
- 使用乐观冲突控制，减少锁竞争
- 中间态设计为可重入，便于失败后重试推进

## 三、数据变更与迁移

### 必须

- **`必须[H]`** 迁移脚本必须正逆成对：每个正向脚本都有对应的逆向脚本，且二者在同一次变更中提交。**违反的表现**：需要回退时才发现逆向脚本不存在
- **`必须[H]`** 结构变更与数据迁移必须拆为独立步骤，各自可独立执行与回退。兼容性判据见 `03-change-compatibility`。**违反的表现**：中途失败后处于新旧混合的不一致状态
- **`必须[H]`** 每个迁移必须有对应的回退脚本，且回退在执行前已验证可用。**违反的表现**：迁移出错后无法恢复
- **`必须[H]`** 迁移必须可重入：重复执行结果一致，不产生重复数据与二次修改。**违反的表现**：中断后重试导致数据被处理两次
- **`必须[H]`** 大规模迁移必须分批执行，每批之间可校验、可中止、可恢复。**违反的表现**：一次性全量迁移长时间占用资源并阻塞业务
- **`必须[H]`** 迁移执行前必须留存可恢复的数据状态，并确认恢复手段可用。**违反的表现**：数据被错误改写且无法还原
- **`必须[H]`** 迁移必须先在与生产同构的环境完成验证，验证记录须留存。**违反的表现**：脚本在生产首次执行，问题在生产暴露
- **`必须[H]`** 迁移影响的数据量必须事先评估，超出写放大边界须分批。**违反的表现**：预期改百行实际改百万行
- **`必须[H]`** 迁移执行必须留下记录：执行人、执行时间、影响范围、执行结果。**违反的表现**：数据异常时无法判断是否与迁移相关

### 推荐

- 迁移脚本与代码同仓管理，版本对应关系明确
- 迁移前后执行数据校验，比对关键统计量
- 高风险迁移在低峰期执行并全程观测

## 四、缓存

### 必须

- **`必须[H]`** 缓存查询必须区分缓存三态，不得将空值与未命中混为一谈。**违反的表现**：已确认不存在的数据被反复回源查询
- **`必须[H]`** 缓存故障必须与数据不存在严格区分，缓存不可用时不得返回空结果。**违反的表现**：缓存故障期间业务判定数据不存在，产生错误结果
- **`必须[H]`** 缓存不可用时必须能降级至数据源，且降级后对数据源的压力须受控。降级要求见 `06-resilience`。**违反的表现**：缓存故障瞬间全量流量压垮数据源
- **`必须[H]`** 必须防止对不存在数据的反复回源。**违反的表现**：无效请求穿透缓存直达数据源
- **`必须[H]`** 缓存失效时间必须打散，禁止大批缓存同时失效。**违反的表现**：失效时刻产生回源尖峰
- **`必须[H]`** 同一数据的并发回源必须收敛，不得每个请求各自回源。**违反的表现**：热点数据失效瞬间产生大量重复回源
- **`必须[H]`** 缓存与数据源的一致性策略必须显式声明，包括更新时序与最大不一致窗口。**违反的表现**：更新后读到旧值，业务认为更新失败
- **`必须[H]`** 缓存键必须包含区分数据版本与环境的信息，禁止跨环境共用缓存键空间。四面隔离见 `08-config-environment`。**违反的表现**：非生产写入的数据被生产读取
- **`必须[H]`** 缓存容量必须有上限与淘汰策略，禁止无限增长。**违反的表现**：缓存占用持续增长直至资源耗尽
- **`必须[H]`** 缓存命中率、回源量、缓存故障必须可观测。**违反的表现**：缓存已基本失效但无人察觉

### 推荐

- 写操作后主动失效相关缓存，而非仅依赖过期
- 热点数据的失效时间与回源成本匹配
- 多级缓存明确各级职责与失效传播方式

- 缓存三态实现与一致性策略对照 → `examples/`

## 五、数据生命周期

### 必须

- **`必须[H]`** 每类数据必须声明保留期与到期处置方式。**违反的表现**：数据无限增长，查询性能持续劣化
- **`必须[H]`** 「目录或文档未提及」不等于「数据不存在分层或归档」。访问历史数据前必须确认其实际存储位置与访问方式。**违反的表现**：按当前存储查询历史数据得到空结果，并据此得出错误结论
- **`必须[H]`** 数据分区与分片键必须与主要查询模式匹配，并记录选型依据。**违反的表现**：主要查询无法利用分区，每次全量扫描
- **`必须[H]`** 跨分层查询必须明确各层的访问方式与限制，不得假设接口一致。**违反的表现**：按热层写法查询归档层，查询失败或代价极高
- **`必须[H]`** 数据删除必须遵循分级要求，敏感数据删除须确认不可恢复。数据分级见 `14-security-baseline`。**违反的表现**：删除仅为逻辑标记，数据仍可被读取
- **`必须[H]`** 数据导出与外传必须遵循数据分级与最小化原则。**违反的表现**：导出文件包含远超所需的敏感字段

### 推荐

- 归档策略与查询需求一并设计，避免归档后无法访问
- 数据量增长趋势纳入常态观测
- 冷热分层的判定标准显式声明并可查

### 参考

- 数据分层访问方式与保留期策略 → `examples/`
