# 14 安全基线

> 覆盖输入校验与注入、认证授权与最小权限、密钥管理、数据分级与个人信息、依赖与供应链、审计、危险操作。
> **本维度定义「不可信输入」「数据分级」「不可逆操作」三个概念，其余维度引用不重述。**
> 安全在**设计阶段**即须纳入考量，不是编码完成后的检查项。

## 概念定义

| 概念 | 定义 |
|---|---|
| **不可信输入** | 任何非本服务代码产生的数据：调用方入参、上游响应、配置值、消息内容、文件内容、数据存储中的历史数据。**内部来源不等于可信** |
| **数据分级** | 按泄露后果对数据分级，至少区分：公开、内部、敏感（个人信息与业务机密）、凭据。各级对应不同的存储、传输、日志与导出规则 |
| **不可逆操作** | 执行后无法通过常规手段还原的操作：数据删除、批量覆盖、资源销毁、外部通知发出、资金与权限变更 |

## 一、输入校验与注入防护

### 必须

- **`必须[H]`** 全部不可信输入必须在进入业务逻辑前完成校验：类型、值域、长度、枚举、格式。接口校验要求见 `04-api-contract`。**违反的表现**：非法值深入系统，在远离入口处引发不可解释的异常
- **`必须[H]`** 校验必须采用白名单方式（声明什么合法），不得采用黑名单方式（声明什么非法）。**违反的表现**：未被列举的攻击形态直接绕过
- **`必须[H]`** 校验失败必须拒绝请求，禁止清洗后继续、禁止截断后继续、禁止使用默认值替代。**违反的表现**：清洗逻辑本身被绕过，或清洗后语义已变而无人察觉
- **`必须[H]`** 数据查询必须参数绑定；无参数绑定通道时使用类型化白名单完整匹配，且标识符类只走枚举白名单。**违反的表现**：输入可改变查询语义，造成越权访问或数据损坏
- **`必须[H]`** 构造命令、路径、模板、查询语句时不得直接拼接外部输入。**违反的表现**：输入被解释为指令而非数据
- **`必须[H]`** 路径参数必须限定在允许范围内，禁止外部输入决定完整路径。**违反的表现**：可读写预期范围之外的任意位置
- **`必须[H]`** 反序列化外部数据必须使用安全方式，不得还原为任意类型。**违反的表现**：构造的数据在还原过程中触发非预期执行
- **`必须[H]`** 输出到其他解释环境时必须按目标环境转义。**违反的表现**：数据在下游被解释为指令
- **`必须[H]`** 外部提供的文件与文档视为不可信输入：不执行其中的可执行内容，文件名须规范化处理，大小须设上限。**违反的表现**：处理外部文件过程中触发非预期执行
- **`必须[H]`** 对外发起的请求目标必须受控，不得由外部输入决定访问地址。**违反的表现**：服务被用作跳板访问内部资源

### 推荐

- 校验规则与契约定义同源，避免两处维护
- 校验失败的响应不透露内部校验规则细节
- 在系统边界集中校验，内部层次不重复实现

- 白名单校验模式与注入防护清单 → `examples/`

## 二、认证与授权

### 必须

- **`必须[H]`** 每个对外接口必须明确其认证要求，无需认证的接口须显式声明并说明理由。**违反的表现**：遗漏认证的接口长期暴露
- **`必须[H]`** 访问他人数据的操作必须校验归属关系，不得仅凭标识存在即放行。**违反的表现**：修改标识即可读写他人数据
- **`必须[H]`** 授权校验必须在服务端执行，不得依赖调用方传入的权限信息。**违反的表现**：伪造权限标识即可越权
- **`必须[H]`** 权限判定必须默认拒绝，未显式授权即拒绝。**违反的表现**：新增资源默认可访问
- **`必须[H]`** 权限必须遵循最小化：只授予完成职责所需的最小范围。**违反的表现**：一处失守即全面失守
- **`必须[H]`** 内部调用同样需要身份与权限控制，不得因来源为内部而免检。**违反的表现**：任一内部服务被攻破即可调用全部内部能力
- **`必须[H]`** 权限变更必须留下审计记录。**违反的表现**：权限被提升而无人知晓
- **`必须[H]`** 认证凭证必须有有效期与失效机制，不得长期有效且无法撤销。**违反的表现**：凭证泄露后无法止损

### 推荐

- 权限模型集中定义，避免散落在各处的判断逻辑
- 高危操作要求额外确认或更强的认证
- 定期复核已授予权限，回收不再需要的授权

### 参考

- 权限校验核对清单与最小权限划分方法 → `examples/`

## 三、密钥与凭据

### 必须

- **`必须[H]`** 凭据仅从运行时环境注入，禁止写入代码、配置文件、构建产物、日志、错误信息与文档。配置管理要求见 `08-config-environment`。**违反的表现**：凭据随代码与制品分发，泄露面覆盖全部有访问权限者
- **`必须[H]`** 凭据一旦进入版本库即视为已泄露，必须立即轮转，清理历史不能替代轮转。**违反的表现**：只删除记录而不换凭据，泄露持续有效
- **`必须[H]`** 凭据必须按用途与环境分别签发，禁止跨环境与跨用途复用。**违反的表现**：低安全环境的泄露直接危及生产
- **`必须[H]`** 凭据必须可在不停服的前提下轮转。**违反的表现**：因轮转成本高而长期不换
- **`必须[H]`** 凭据不得出现在可观测数据中，包括日志、指标、调用链与错误响应。日志要求见 `07-observability`。**违反的表现**：凭据随日志扩散至日志系统与备份
- **`必须[H]`** 示例、文档、模板、用例中一律使用占位符。**违反的表现**：示例中的真实凭据被复制到多处

### 推荐

- 凭据设有效期并定期轮转
- 凭据的获取与使用产生审计记录
- 提交前自动检查凭据特征，在进入版本库前拦截

### 参考

- 凭据注入方式与泄露应急流程 → `examples/`

## 四、数据分级与个人信息

### 必须

- **`必须[H]`** 每类数据必须有明确分级，分级决定其存储、传输、日志、导出与留存规则。**违反的表现**：敏感数据按普通数据处理，扩散后无法回收
- **`必须[H]`** 敏感数据不得以明文写入日志、指标、调用链与错误信息。需要标识时使用不可逆处理后的标识。**违反的表现**：个人信息随日志分发至多个系统
- **`必须[H]`** 敏感数据的传输与存储必须加密，加密方式须明确并可审查。**违反的表现**：数据在链路或存储中以明文存在
- **`必须[H]`** 数据获取必须最小化：只取业务实际需要的字段与范围。**违反的表现**：超范围获取的数据成为额外泄露面
- **`必须[H]`** 数据导出与跨域传递必须经审批并留记录，导出内容须按分级脱敏。**违反的表现**：敏感数据被导出至不受控环境
- **`必须[H]`** 非生产环境不得使用未脱敏的生产敏感数据。四面隔离见 `08-config-environment`。**违反的表现**：敏感数据扩散至防护级别更低的环境
- **`必须[H]`** 加密存储的数据不得以明文条件匹配，查询方式须与加密方式匹配。**违反的表现**：查询恒为空集且被误判为数据不存在
- **`必须[H]`** 敏感数据删除必须确认实际不可恢复，逻辑标记不构成删除。数据生命周期见 `09-data-storage`。**违反的表现**：已声明删除的数据仍可被读取

### 推荐

- 分级标注随数据结构定义一同维护
- 敏感字段集中标识，便于自动化检测
- 数据访问产生审计记录，支持事后追溯

### 参考

- 数据分级模型与脱敏方式对照 → `examples/`

## 五、依赖与供应链

### 必须

- **`必须[H]`** 引入新依赖必须评估维护状态、安全记录、许可证与实际必要性，并记录评估结论。**违反的表现**：引入无人维护的依赖，漏洞出现后无修复来源
- **`必须[H]`** 依赖必须锁定确定版本，禁止浮动版本。构建要求见 `13-delivery-release`。**违反的表现**：依赖被替换或投毒而无人察觉
- **`必须[H]`** 依赖必须来自受信任的来源，不得从不可验证的位置获取。**违反的表现**：获取到被篡改的依赖
- **`必须[H]`** 已知高危漏洞必须处置：升级、替换或明确记录缓解措施，不得无处置放行。**违反的表现**：已知漏洞长期存在
- **`必须[H]`** 必须掌握完整的依赖清单，包括间接依赖。**违反的表现**：漏洞通告发布时无法判断是否受影响
- **`必须[H]`** 制品中不得包含非必要内容，减少攻击面。**违反的表现**：制品内含调试工具与源码，为攻击提供便利

### 推荐

- 依赖更新定期进行，避免长期滞后
- 优先选择依赖数量少、维护活跃的组件
- 关键依赖有替代方案评估，避免不可替换

- 依赖引入评估清单与漏洞处置流程 → `examples/`

## 六、审计与危险操作

### 必须

- **`必须[H]`** 安全相关事件必须产生审计记录：认证结果、授权拒绝、权限变更、敏感数据访问与导出、配置与凭据变更。**违反的表现**：安全事件发生后无法还原过程
- **`必须[H]`** 审计记录必须包含操作主体、操作时间、操作对象、操作结果，且主体可追溯到具体身份。**违反的表现**：只知道发生了操作，不知道是谁做的
- **`必须[H]`** 审计记录不得被业务操作方修改或删除。**违反的表现**：审计可被篡改，失去证明力
- **`必须[H]`** 不可逆操作必须经二次确认，且确认环节不得被自动化流程跳过。**违反的表现**：一次误操作造成不可恢复的损失
- **`必须[H]`** 不可逆操作必须限定影响范围，范围不明确时不得执行。写放大边界见 `09-data-storage`。**违反的表现**：预期影响少量数据实际影响全量
- **`必须[H]`** 禁止使用强制类指令绕过安全检查与保护机制。**违反的表现**：保护机制被绕过，损失不可恢复
- **`必须[H]`** 生产环境的写操作必须经受控流程执行，禁止直接手工操作。**违反的表现**：手工操作无记录、无评审、无回滚方案
- **`必须[H]`** 高危操作必须具备可恢复手段，无恢复手段时须事先获得明确授权。可回滚性要求见 `13-delivery-release`。**违反的表现**：执行后发现错误且无法恢复

### 推荐

- 危险操作清单显式维护，新增操作时评估是否列入
- 高危操作要求双人确认
- 审计记录的留存期满足合规要求并定期验证可用

### 参考

- 审计事件清单与危险操作处置流程 → `examples/`
