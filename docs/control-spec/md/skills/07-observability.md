# 07 可观测性

> 覆盖日志、指标、调用链、告警。
> **本维度定义「可观测性交付责任」「链路上下文」「可行动告警」三个概念，其余维度引用不重述。**

## 概念定义

| 概念 | 定义 |
|---|---|
| **可观测性交付责任** | 服务出现问题时，**不接触代码的人**能否判断问题存在、影响范围与大致原因。这是开发侧的交付项，不是运维侧的补救项 |
| **链路上下文** | 跨进程传递的请求关联信息，至少含全局唯一的链路标识。用于把分散在多服务的日志、指标、调用记录关联为一次请求 |
| **可行动告警** | 收到后存在明确处置动作的告警。无处置动作的信号属于观测数据，不得配置为告警 |

## 一、日志

### 必须

- **`必须[H]`** 日志必须携带约定的字段基线，缺一不可。**违反的表现**：日志无法按统一维度检索与聚合
- **`必须[H]`** 日志与指标命名必须符合约定，同一语义字段在全部服务中同名。**违反的表现**：跨服务检索需按多套名称分别查询
- **`必须[H]`** 日志必须结构化输出，字段可被机器解析，禁止把变量拼接进自由文本后再由下游正则提取。**违反的表现**：排查需要按文本模式匹配，格式微调即导致检索失效
- **`必须[H]`** 日志等级语义必须明确且一致：错误级仅用于需要人介入的异常，正常业务流程不得使用错误级。**违反的表现**：错误级日志充斥正常流程，真实错误被淹没
- **`必须[H]`** 每条日志必须可关联到具体请求，携带链路标识。无请求上下文的后台任务须携带任务标识。**违反的表现**：并发场景下日志交错，无法还原单次请求过程
- **`必须[H]`** 异常日志必须包含完整错误信息与上下文（操作对象、关键入参摘要、失败阶段），不得只记录一句失败描述。**违反的表现**：只有「调用失败」，无法判断失败对象与原因
- **`必须[H]`** 敏感数据不得写入日志。需要标识时使用不可逆处理后的标识。数据分级定义见 `14-security-baseline`。**违反的表现**：凭据或个人信息随日志落盘并分发至日志系统
- **`必须[H]`** 日志输出不得阻塞业务主流程，日志系统不可用时业务必须继续运行。**违反的表现**：日志后端故障导致服务整体不可用

### 推荐

- 按等级分级采样：异常全量保留，正常流程抽样
- 日志量与保留期在设计阶段核算，避免上线后被动限流
- 同一语义字段在全部服务中使用同一字段名
- 关键状态变更（配置生效、熔断开合、降级开关）输出为独立可检索事件

- 日志字段基线清单与结构化输出示例 → `examples/`

## 二、指标

### 必须

- **`必须[H]`** 新增或变更的对外接口必须有指标埋点，不得只改逻辑不加观测。**违反的表现**：新功能上线后无任何可观测数据，问题靠用户上报
- **`必须[H]`** 指标维度基数必须受控，上线前须核算其取值组合规模。**违反的表现**：维度爆炸拖垮监控系统，且往往在上线后才暴露
- **`必须[H]`** 每个对外接口必须覆盖四类指标：请求量、失败量或失败率、耗时分布、依赖调用结果。**违反的表现**：只有请求量，无法判断服务是否健康
- **`必须[H]`** 耗时指标必须明确口径（累计值、平均值、分位值），口径必须在指标定义中可查。**违反的表现**：把累计耗时当平均耗时解读，得出错误结论
- **`必须[H]`** 指标维度取值必须为有限枚举集。请求标识、用户标识、时间戳等无界取值不得作为维度。**违反的表现**：维度组合爆炸，监控系统存储与查询被拖垮
- **`必须[H]`** 失败指标必须能区分失败类型（业务失败、依赖故障、超时、限流、熔断），不得只有一个失败总数。**违反的表现**：失败率上升但无法判断原因方向
- **`必须[H]`** 指标上报不得阻塞业务主流程，监控后端不可用时业务必须继续运行。**违反的表现**：启动时等待监控组件就绪，组件不可用则服务无法启动
- **`必须[H]`** 指标定义必须包含含义、单位、维度说明，可被非作者理解。**违反的表现**：指标只有作者看得懂，交接后无人敢用

### 推荐

- 显式定义服务级目标，作为告警阈值与容量评估的基准
- 区分业务指标与技术指标，分别面向业务方与开发者
- 关键依赖的调用指标与自身指标同等对待
- 变更事件上报为可观测事件，便于将指标波动与变更关联

### 参考

- 四类指标定义模板与维度基数核算方法 → `examples/`

## 三、调用链

### 必须

- **`必须[H]`** 链路上下文必须在进程内全程透传，跨进程调用必须携带，异步任务与消息投递必须显式传递。**违反的表现**：链路在异步边界断开，只能追踪到一半
- **`必须[H]`** 日志与调用链必须可双向关联：由链路标识能检索到全部日志，由日志能定位到所属链路。**违反的表现**：两套系统各自独立，排查需人工拼接
- **`必须[H]`** 调用链记录必须覆盖全部跨进程调用与关键内部阶段，不得只记录入口。**违反的表现**：只知道请求慢，不知道慢在哪一段
- **`必须[H]`** 调用链记录必须包含调用结果与错误信息，不得只记录耗时。**违反的表现**：能看到调用发生，看不到是否成功
- **`必须[H]`** 采样策略必须保证异常请求被完整记录，不得对异常请求采样丢弃。**违反的表现**：出问题的请求恰好未被采样，无链路可查

### 推荐

- 入口处生成链路标识，并在响应中返回给调用方便于问题上报
- 采样比例可运行时调整，故障期间临时提高
- 调用链记录中附带关键业务标识，支持按业务维度检索

## 四、告警

### 必须

- **`必须[H]`** 每条告警必须可行动：存在明确处置动作。无处置动作的信号只作观测数据，不得配置为告警。**违反的表现**：告警持续触发但无人处理，最终全员屏蔽
- **`必须[H]`** 每条告警必须有明确的责任归属，不得只发送至无人负责的公共接收方。**违反的表现**：告警发出但无人认领
- **`必须[H]`** 告警必须分级，不同级别对应不同响应时限与通知方式。**违反的表现**：所有告警同等对待，重要告警被大量次要告警淹没
- **`必须[H]`** 告警内容必须包含定位所需的最小信息：受影响对象、影响范围、触发条件、可直接跳转的排查入口。**违反的表现**：只有一句「异常」，处理者需从零查起
- **`必须[H]`** 新增或变更对外接口时必须评估告警覆盖，不得只加指标不加告警。**违反的表现**：指标齐全但无人盯，故障靠用户上报
- **`必须[H]`** 核心不可见风险必须覆盖告警：配置是否生效、启动是否就绪、降级与熔断是否已触发。生效可见性要求见 `08-config-environment`。**违反的表现**：服务进程存活但实际不可服务，监控显示一切正常

### 推荐

- 告警阈值基于服务级目标设定，而非凭经验取值
- 配置抑制、聚合与静默窗，降低重复告警噪声
- 定期回顾告警有效性，清理长期无处置动作的告警
- 变更期间的告警单独标注，便于区分变更引发与自发故障

- 告警分级矩阵与告警内容模板 → `examples/`
