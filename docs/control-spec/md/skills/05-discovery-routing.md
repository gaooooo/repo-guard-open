# 05 服务发现与路由

> 覆盖注册与反注册、健康检查、优雅上下线、负载均衡、就近与多活、灰度与染色、环境隔离寻址。
> **本维度定义「可服务性」「优雅上下线」「染色标记」三个概念，其余维度引用不重述。**

## 概念定义

| 概念 | 定义 |
|---|---|
| **可服务性** | 实例当前是否能够正确处理请求。**进程存活不等于可服务**：依赖未就绪、配置未加载、资源耗尽均属不可服务 |
| **优雅上下线** | 上线时先就绪再接流量；下线时先摘流量、再排空在途请求、最后停止进程。任一步缺失即非优雅 |
| **染色标记** | 附加在请求上、用于路由决策的标识（灰度批次、压测流量、指定链路）。**须全链路透传，中途丢失即失效** |

## 一、注册与发现

### 必须

- **`必须[H]`** 调用方不得硬编码目标实例地址，必须通过服务发现获取。**违反的表现**：目标实例变更需要调用方同步发布
- **`必须[H]`** 实例必须在确认可服务之后才注册，不得在启动开始时立即注册。**违反的表现**：尚未就绪的实例接收流量并失败
- **`必须[H]`** 实例异常终止后必须能被自动摘除，不得依赖实例主动反注册。**违反的表现**：进程崩溃后注册信息残留，流量持续打向已死实例
- **`必须[H]`** 服务发现组件不可用时必须有降级路径：使用最近一次有效的实例列表继续服务。降级要求见 `06-resilience`。**违反的表现**：注册中心故障导致全部服务连锁不可用
- **`必须[H]`** 实例列表为空时必须明确处置并产生告警，不得静默重试或退化为默认地址。**违反的表现**：调用静默失败，或意外打到默认地址
- **`必须[H]`** 注册与反注册必须产生可观测事件。可观测要求见 `07-observability`。**违反的表现**：实例数异常波动但无从追溯

### 推荐

- 本地缓存实例列表并持久化，进程重启后仍可用
- 实例列表变更平滑生效，避免瞬时全量重建连接
- 注册信息中携带实例版本与环境标识，便于路由与排查

### 参考

- 服务发现降级策略与实例列表缓存方式 → `examples/`

## 二、健康检查

### 必须

- **`必须[H]`** 健康检查必须反映真实可服务性，不得恒定返回成功。**违反的表现**：实例已无法处理请求但仍被视为健康，流量持续打入
- **`必须[H]`** 存活检查与就绪检查必须语义分离：存活判断是否需要重启，就绪判断是否可接收流量。**违反的表现**：依赖短暂不可用触发实例重启，故障被放大
- **`必须[H]`** 就绪检查必须覆盖强依赖的可用性，不得只检查进程自身。强依赖定义见 `06-resilience`。**违反的表现**：强依赖不可用但实例仍被判定就绪
- **`必须[H]`** 存活检查不得依赖外部依赖的可用性。**违反的表现**：外部依赖抖动导致全部实例被同时重启
- **`必须[H]`** 健康检查自身必须轻量且设超时，不得因检查逻辑耗时而误判。**违反的表现**：检查超时被判定为不健康，实例被反复摘除
- **`必须[H]`** 实例因资源耗尽或内部状态异常而不可服务时，必须能主动将自身置为不就绪。**违反的表现**：实例已过载但仍持续接收新流量直至彻底失效

### 推荐

- 就绪状态的变化产生可观测事件与告警
- 提供可人工触发的摘流量入口，用于排查与演练
- 检查结果包含不就绪的具体原因，便于定位

### 参考

- 存活与就绪检查的判定项划分 → `examples/`

## 三、优雅上下线

### 必须

- **`必须[H]`** 上线必须先就绪后接流量：初始化、配置加载、依赖连接建立完成前不得接收请求。**违反的表现**：新实例上线瞬间产生一批失败请求
- **`必须[H]`** 下线必须按序执行：先从服务发现摘除、等待流量摘除生效、排空在途请求、最后停止进程。**违反的表现**：进程直接退出，在途请求全部失败
- **`必须[H]`** 摘除生效与实际停止之间必须有等待期，等待期不短于调用方感知实例列表变更所需时间。**违反的表现**：调用方仍持有旧实例列表，请求打向已停止实例
- **`必须[H]`** 排空期间必须拒绝新请求但完成已接收请求，排空须设上限时间。**违反的表现**：个别长请求导致下线无限期挂起
- **`必须[H]`** 必须响应终止信号并触发下线流程，不得忽略终止信号等待强制终止。**违反的表现**：每次发布都产生一批失败请求
- **`必须[H]`** 下线流程必须覆盖非请求型工作：后台任务、消息消费、定时任务须一并停止并保证处理完整性。**违反的表现**：消息消费中途停止导致消息丢失或重复

### 推荐

- 新实例接流量时逐步增加权重，避免冷启动阶段被打满
- 下线各阶段产生可观测事件，便于确认流程完整执行
- 排空上限时间按接口最长预期耗时设定

### 参考

- 上下线时序与信号处理流程 → `examples/`

## 四、负载均衡

### 必须

- **`必须[H]`** 负载均衡策略必须与依赖特性匹配，并记录选型依据。**违反的表现**：策略与实际负载特征不符，实例间负载严重不均
- **`必须[H]`** 必须具备故障实例的自动隔离与恢复探测能力，不得持续向失败实例发送请求。熔断要求见 `06-resilience`。**违反的表现**：单个故障实例持续接收并失败其份额的请求
- **`必须[H]`** 需要会话保持时必须显式声明其依据与失效处置，不得隐式依赖请求恰好落在同一实例。**违反的表现**：实例变动后会话状态丢失，行为异常且难以复现
- **`必须[H]`** 重试必须避开刚失败的实例。重试要求见 `06-resilience`。**违反的表现**：重试反复打到同一故障实例，重试完全无效

### 推荐

- 实例权重可运行时调整，用于灰度与故障处置
- 优先使用能感知实例实际负载的策略，而非仅按序分配
- 单实例的连接数与并发数设上限，避免单点被打满

### 参考

- 负载均衡策略对照与选型判据 → `examples/`

## 五、就近访问与多活

### 必须

- **`必须[H]`** 跨地域或跨可用区部署时，路由必须优先就近，并具备跨区兜底能力。**违反的表现**：请求跨区往返，耗时不可控
- **`必须[H]`** 就近路由必须在本地实例全部不可用时自动切换至其他区，切换条件与恢复条件须明确。**违反的表现**：本区故障时请求持续失败而不切换
- **`必须[H]`** 多活部署必须明确数据一致性边界：哪些数据本区自治、哪些需要跨区一致。**违反的表现**：跨区并发写产生数据冲突且无解决规则
- **`必须[H]`** 路由键必须全局统一，同一业务实体在各层路由到同一区。**违反的表现**：同一实体的请求分散到多区，数据不一致

### 推荐

- 跨区调用比例作为常态监控指标
- 区级故障的切换能力定期演练验证
- 跨区调用的超时与本区分别设定

### 参考

- 就近路由与跨区兜底策略 → `examples/`

## 六、灰度与染色

### 必须

- **`必须[H]`** 染色标记必须全链路透传，跨进程调用、异步消息、后台任务均须携带。链路上下文要求见 `07-observability`。**违反的表现**：染色在某一跳丢失，灰度流量流入正式链路
- **`必须[H]`** 灰度路由规则必须可精确表达并可快速调整，不得依赖实例部署顺序隐式实现。**违反的表现**：无法控制灰度范围，也无法快速收回
- **`必须[H]`** 灰度流量必须在可观测数据中可区分，指标与日志须带灰度标识。**违反的表现**：灰度异常被正式流量数据稀释，无法及时发现
- **`必须[H]`** 灰度必须可一键收回，收回后流量立即回到稳定版本。**违反的表现**：灰度出问题后只能等待回滚发布，影响持续扩大
- **`必须[H]`** 压测流量必须染色并与正式流量隔离，不得写入正式数据。四面隔离要求见 `08-config-environment`。**违反的表现**：压测数据污染生产
- **`必须[H]`** 无法识别染色标记的下游必须在灰度前确认处置方式，不得默认按正式流量处理。**违反的表现**：灰度流量在下游被当作正式流量产生真实副作用

### 推荐

- 染色标记的字段名与取值在全部服务中统一
- 灰度按可控维度划分批次，避免按随机比例放量
- 灰度期间的关键指标单独看板，与正式流量对比

### 参考

- 染色透传方式与灰度路由规则示例 → `examples/`

## 七、环境隔离寻址

### 必须

- **`必须[H]`** 寻址必须受环境约束：非生产实例不得解析到生产实例，生产实例不得解析到非生产实例。四面隔离定义见 `08-config-environment`。**违反的表现**：非生产流量打入生产，或生产依赖非生产实例
- **`必须[H]`** 环境约束必须在寻址层强制实施，不得依赖配置正确性作为唯一保障。**违反的表现**：一处配置写错即造成跨环境调用
- **`必须[H]`** 跨环境调用必须被拒绝并产生告警，不得静默放行。**违反的表现**：跨环境调用长期存在而无人发现
- **`必须[H]`** 实例注册信息必须携带环境标识，供调用方校验。**违反的表现**：调用方无法判断目标实例所属环境

### 推荐

- 不同环境使用独立的服务发现命名空间，物理隔离优于逻辑过滤
- 跨环境调用的检测作为常态巡检项

### 参考

- 环境隔离寻址实现方式 → `examples/`
