# 七层控制面

> 按 Agent 执行时**谁判定、写到哪个控制点**分成七层。左侧开发阶段菜单是给人找的；**七层才是分类**。

## 读者与范围

| | |
|---|---|
| **给谁读** | 要在业务仓接入 repo-guard 的开发；写红线 / 过程门禁 / 技能的人 |
| **用来干什么** | 查某一层管什么、配在哪个文件、何时生效、要不要人拍板 |
| **不管** | 产品需求怎么写、云上容量与成本、代码托管平台账号权限怎么开（只告诉你要配 CODEOWNERS，不代替平台文档） |
| **技能库 01～15** | 后端提供的原文，本站只渲染、不改写 |

控制面各页结构：一句话 → 用途 → 如何配置 → **字段说明** → **真实 JSON 示例** → 是否人审 → 时机/原理。

## 七层

| # | 层 | 一句话 | 写在业务仓哪里 | 菜单入口 |
|---|---|---|---|---|
| 1 | 工程事实 | 代码读不出、每次必须看见 | `CODEBUDDY.md` / `.codebuddy/repo-facts.json` / `facts.json` | 知识库 |
| 2 | 技能库 | 怎么做（拉） | `skills/*/SKILL.md`、`.codebuddy/standards/` | 技能库 |
| 3 | 红线 | 对外还在用的名字不许少 | `.codebuddy/redlines.json` | Agent harness |
| 4 | 过程门禁 | 该查的查了没有 | `.codebuddy/process-gates.json` | Agent harness |
| 5 | 人审 | 何时把决定权交回人 | `.codebuddy/human-review.json`、`facts.json` 的 stopConditions | 人审 |
| 6 | 合并门禁 | 进不进主干、危险命令能不能跑 | CI / CODEOWNERS / 宿主 `permissions.ask` | 工程 |
| 7 | 图谱 | 现算谁在用、波及谁 | MCP + `repo-facts.publicLayer` | Agent harness |

## 术语

| 词 | 意思 |
|---|---|
| **公共层** | `repo-facts.json` 的 `publicLayer` 目录。改其中**已有**文件前必须先查 impact |
| **protects** | 红线要数的标识符。没有它等于没锁 |
| **confirmed** | 红线/禁改条目上的人确认。`false` 不当硬拦 |
| **admission** | 过程门禁总闸。打开后禁改/范围/新建查图才可能硬拦。**公共层 impact 不靠它** |
| **拉** | 技能只注册 name+description，模型判断相关才展开正文 |
| **推 / 注入** | 会话开始主动塞进上下文，不拦写入 |
| **软名单** | `stopConditions`：开场告诉模型「这时问人」，不听也拦不住 |
| **硬开关** | `human-review.json`：红线命中后弹窗，不点过不去 |
| **canUseTool** | 宿主 SDK 在工具执行前的回调。指定 leader 审批走这里，不是本机弹窗 |
| **impact / similar / hot / lib_search** | 图谱工具：波及谁 / 同类怎么写 / 高扇入 / 组件库有没有 |
| **require_tool** | 规范条目：写某类路径前必须先调过指定图谱工具 |
| **G-01～G-07** | 合入主干的流水线/平台门禁，模型只读结论 |

## 何时生效

| 层 | 只注入 | 写前 | 写后 | 停时 | 合入 |
|---|---|---|---|---|---|
| 工程事实 | 会话开始、压缩后；任务路由在提问时 | — | — | — | — |
| 技能库 | 相关时展开 SKILL.md | 一般不拦 | 规范可为 remind | — | 少数条款进 CI |
| 红线 | 开场只给 id 与一句话 | **真 diff 里 protects 变少 → deny/ask** | — | — | audit 可挂 CI |
| 过程门禁 | 开场可推纪律 | **公共层未查 impact → deny**；循环/范围/新建查图看开关 | 超长文件提醒 | 交付门认没跑过测试 | 不拦 git commit |
| 人审 | 软名单开场注入 | 红线命中后 ask（若打开） | — | — | leader 合入不在这一层 |
| 图谱 | — | 只读「本轮查过没」；不在 hook 里建图 | — | — | `scan` 可挂 CI |
| 合并门禁 | — | 宿主 ask 拦危险 Bash | — | 不在 Stop 硬拦提交 | **CI / 保护分支 / CODEOWNERS** |

空格「—」表示这一层通常不管该时机。

## 门禁和规范怎么分工

- **G-01～G-07**（见菜单「门禁索引」或 `md/00-gate-index.md`）是流水线/平台的机械结论：通过或不通过。模型只读结论，不读阈值。
- **01～15** 是机器帮不了的语义要求，原文在技能库对应 markdown，本目录不改这些文件。
- 同一要求不两边重复。

## 同一条需求会经过哪些层

1. **事实**：开场已注入公共层与组件库。
2. **过程**：没查 impact 不准改公共层已有文件。
3. **图谱**：impact 给出波及谁。
4. **红线**：受保护名字变少 → 拦住。
5. **人决策**：破例走本机 ask，或 `canUseTool` 找 leader。
6. **合并**：`git push` 先问人；MR 过 CI 与必审人。

## 配置示例从哪来

控制面各页的 JSON 取自业务仓实际文件：身份服务用 `backend-agent-identity`；**组件规范 / UI 规范**用前端仓 `saas-web`。条数不足 10 的按该仓语义补全，并在标题里标明「补全」。
