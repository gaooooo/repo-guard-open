# 红线 · 规范（汇报稿）

来源：03 接口/数据兼容、04 契约字段、08/14 凭据、09 字段删除、业务状态机。

## 收什么（必须能写成 protects + paths）

1. 已发布接口：字段只增不删；标识、类型、语义不得变。
2. 不得收紧既有入参、不得随意扩张出参枚举。
3. 数据结构字段删除/重命名必须走废弃，禁止一步删。
4. 凭据禁止写入代码、配置文件、构建产物、日志、文档。
5. 业务受保护符号（状态枚举、对账字段、鉴权判定）禁止静默删改。

## 不收什么

风格、超时数值、覆盖率、文档语气。
**意图不清、需求多种解读、语义变了但标识符还在** —— 收不成 protects，写人审软名单 `stopConditions`，不要写红线。

## 落点

.codebuddy/redlines.json 的 `rules`：`protects`+`paths` 是锁，`reason` 是原因，必须进 git。
Write/Edit 真 diff 里标识符次数变少 → deny；人审开关打开则改为 ask。引擎不判断「清不清」。
Bash 绕道只提醒。没有 protects 等于一句 prompt，拦不住。
配完必须跑 audit（守空气 / paths 后门 / evidence 行号）。
