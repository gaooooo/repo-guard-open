# 人审 · 规范（汇报稿）

来源：15§一 自主边界、14§六 不可逆、13 评审与发布、03 破坏性变更、09 迁移。

## 必须停下来问人

1. 需求不明确或多种合理解读
2. 合入主干、发布、生产环境写操作、权限变更
3. 不可逆操作（删除、全量更新、无回滚方案）
4. 破坏性接口/数据变更、结构变更与迁移
5. 红线命中但意图需要人确认（人审开关打开时）
6. 方案本身有问题：提出异议并停止，不得自行换方案

## 仍然直接 deny（不问）

- 未查公共层 impact（手续）
- 循环失控、禁改清单（冻结）

## 落点（两半，都不是红线）

| | 软名单 | 硬开关 |
|---|---|---|
| 文件 | `.codebuddy/facts.json` 的 `stopConditions` | `.codebuddy/human-review.json` |
| 时刻 | T4 SessionStart 注入 | T7b permissionDecision: ask |
| 收什么 | 上面 1–4、6：收不成符号的「这时问人」 | 上面 5：红线**已经命中**后问人破不破例 |
| 硬吗 | 否，模型自觉 | 弹窗。默认 enabled: false，红线仍 deny |

宿主 permissions.ask（合入/生产）是合并门禁侧，不要写进 stopConditions。
